# Изменения программы Fasad

## 05.11.2026 — упрощён запуск и сохранение проектов

- Основной запуск — `New project.py` (команда AutoCAD `ФАСАД` / `FASAD`).
- Убрана привязка к чертежу `Чертеж1.dwg`: программа работает с активной вкладкой AutoCAD.
- Имя проекта определяется именем активного DWG без расширения.
- Перед построением программа ищет в `C:\cad\Projects` DWG с таким именем. При совпадении показывает запрос: «Проект <имя> есть в базе проектов, перезаписать?». При отказе построение отменяется.
- Если проект не найден, создаётся папка `C:\cad\Projects\<имя>`; DWG проекта сохраняется туда как `<имя>.dwg`.
- Сохранение чертежа и проектных файлов запускается только после успешного построения хотя бы одного витража. Для проекта в другой папке исходный активный чертёж сохраняется в проектную папку через AutoCAD `SaveAs`.
- Имя Excel берётся из поля «Название» окна «Исходные данные». Excel, настройки и данные раскроя хранятся в папке проекта.
- Удалён отдельный сценарий `edit project.py` и соответствующая команда редактирования из `Фасад.lsp`.
- Проверка активного чертежа после окна исходных данных теперь использует полный путь, чтобы не продолжить построение, если пользователь переключился на другую вкладку.

### Затронутые файлы

- `New project.py` — единый сценарий построения и сохранения проекта.
- `fasad/projects.py` — поиск DWG проекта и формирование пути нового проекта.
- `fasad/run.py` — сохранение проекта после успешного построения.
- `fasad/acad_link.py` — получение полного пути активного чертежа и сохранение в DWG.
- `fasad/dialog.py` — подтверждение перезаписи проекта.
- `Фасад.lsp` — обновлены команды запуска.
- `СОСТОЯНИЕ.md` — обновлена инструкция.

Проверены синтаксис Python, поиск проекта и защита перезаписи. Работа сохранения и перезаписи в реальном AutoCAD требует отдельной проверки.

## 05.11.2026 — подключен расчёт статики (Lora)

В окно «Исходные данные» добавлены чекбокс **«Считать статику»** и кнопка **«Расчёт нагрузок»**.
Пока галка стоит, активны только «Название объекта», сам чекбокс и кнопка. По кнопке запускается
программа `C:\cad\Lora_2_2` (как отдельный процесс, `main.py --фасад <файл>`). В Лоре считается
как обычно; результат передаётся кнопкой **«Экспорт в FS»** (бывш. «Экспорт *.txt», `pushButton_8`)
или автоматически при закрытии её окна, если расчёт выполнялся. Файл обмена — `статика.json`
в папке проекта (блоки «вход» и «результат»), при повторном открытии проекта фильтры
восстанавливаются.

По результату в окне исходных данных:
- список стоек ограничен профилями не уже выбранной в Лоре глубины (то же для ригелей);
- выбранные в Лоре стойка/ригель подставляются в поля «Стойка»/«Ригель»;
- в Лору передаётся «Суммарная толщина стекла» — сумма стёкол из формулы пакета
  (6-16-6-16-6 → 18 мм), а не толщина заполнения;
- при тяжёлом стекле (правило «тяжелый» в карточке) список вариантов комплектации
  сокращается до «Тяжелые КПС 846» (заполнение ≤ 48) / «Тяжелые КПС 1126» (> 48);
- под списком витражей строка с результатом статики; «ПРОВЕРИТЬ» — если выбранный
  в Лоре профиль не проходит по моментам.

Файлы: новый `fasad/lora_link.py` (запуск, обмен, фильтры); `fasad/dialog.py` (чекбокс, кнопка,
блокировка полей, фильтры); `fasad/run.py` (объект Statics в ask); `systems\КП50К.toml` —
секция `["статика"]` (`путь`, `питон`, `система_лора` = «SIAL KP50K»). В Лоре: `main.py`
(режим `--фасад`: чтение «входа» — название в заголовок, толщина стекла, система;
`_last_calc` в calculate; `export_to_fasad`, `closeEvent`), `UI\Lora2.ui` (текст кнопки).

Проверено без AutoCAD: фильтры по глубине и весу на таблицах КП50К; обмен JSON (в т.ч.
`система_лора` из toml); прогон Лоры offscreen (предзаполнение → расчёт → экспорт по closeEvent,
вес стёкол сошёлся с формулой). Реальный запуск из окна в AutoCAD — проверить пользователю.

Исправлено в тот же день: (1) после возврата из Лоры поля окна оставались неактивными —
разблокировка теперь вызывается явно, а не через обработчик галки; (2) в Лору передаётся
сумма толщин стёкол из формулы пакета (6-16-6-16-6 → 18 мм), а не толщина заполнения.

Исправлено 05.11 (после разбора построения Чертеж1): (3) закладные ригеля не попадали в чертёж —
шифр закладной с запятой («КП1336-131,5-б») ломал имя слоя (запятая запрещена в AutoCAD),
18 объектов молча не создавалось; имена слоёв чистятся от запрещённых символов
(`sections.py::_layer_safe`, запятая → точка: `MARK_ЗАКЛ_КП1336-131.5-б`); (4) фильтр «Тяжелых»
вариантов по весу стекла теперь ищет любое имя с префиксом «Тяжелые»; (5) тяжёлые подкладки
КПС 846/1126 не для любой толщины пакета: если стекло тяжёлое (>200 кг), а у текущей толщины
нет тяжёлого варианта (для 50 мм его нет по каталогу), предупреждение предлагает сменить толщину
(`facade.py::_has_heavy_kit`, подсказка в окне после статики — `lora_link.py::heavy_thickness_hint`);
после смены толщины фильтр подставляет тяжёлый вариант сам.

Дополнено 05.11: (6) Лора **запоминает сеанс** — все поля ввода и списки сохраняются при закрытии
в `Lora_2_2\save_data\последний_сеанс.json` и восстанавливаются при следующем запуске
(при запуске из Фасада его данные имеют приоритет); (7) Фасад передаёт в Лору **размеры по осям
текущего витража** (`lora_link.py::cell_geometry`): b1 — приведённая ширина грузовой площади
(взвешена по высотам ячеек), b2 = max шаг стоек − 20, l1/l2 — высоты пакета по большей/меньшей
сторонам расчётного ригеля (несущего самый большой пакет) − 24, l2 у крайнего ригеля 0, h_m —
высота стойки. Проверено на схемах пользователя (вариант 1: l2=0; вариант 2: l2=476).
(8) Разрыв «Лора разрешает по прочности — применить нельзя по креплению» закрыт: по весу стекла
из статики определяются требуемые отверстия закладной (`fixing_holes`), список ригелей в окне
ограничивается профилями с такой закладной (`beams_with_fixing`/`wrap_beams_fixing`; под болты «б»
это 9 ригелей от 124,5 мм), а если Лора подобрала непригодный ригель — всплывает предупреждение
`fixing_warning_text`, в строке статики появляется заметка.
(9) Окно исходных данных больше экрана: высота подгоняется под экран сжатием списка витражей,
заметка о ригеле переносится на 2 строки (своя строка с wraplength), текст «Проверить» в отчёте
ограничен высотой экрана.
(10) «Таблица профилей: марка изменилась» при смене профиля в окне: предупреждение выдавалось
на каждую марку, т.к. база в чертеже ещё от старого расчёта; теперь предупреждение только о
реальной ручной правке (артикул в таблице отличен от записанной базы) — смена профиля в окне
таблицу молча перезаписывает, второй перезапуск не нужен (`facade.py::build`).
(11) Сечение молча оставляло профиль из узла, если выбранного профиля нет в библиотеке блоков
(блок `кпс 801_830` вместо «КПС 801») — теперь замечание «в библиотеке нет блока «X» — оставлен
профиль из узла» (`library.py::Source.node`). В файле библиотеки блоки переименованы в ровные
артикулы: `кпс 801_830` → «КПС 801», `кпс 829_830` → «КПС 829» (копия — `.dxf.перед_переименованием.bak`).
Причина «хвостов»: старые записи «КПС 801_830»/«КПС 829_830» в базе Лоры (пользователь удалил;
КПС 830 — это закладная к ригелю, не профиль). В библиотеке остались два блока-сироты
`кпс 371_кан`/`кпс 372_кан` без соответствия в таблицах — не используются, безвредны.
(12) Закладные на фасаде: подпись — выбранная закладная из таблицы креплений (например
«КПС 830-225,5-б»), а контур брался жёстко из ключа «КП1336/ригель из карточки» — для КПС 830
подписывала одно, рисовала форму КП1336. Теперь контур ищется только своего семейства
(«СЕМЕЙСТВО/выбранный ригель», фолбэк «СЕМЕЙСТВО/ригель карточки» — старые снятые данные
работают); чужой формой не заменяется — условный прямоугольник + замечание
«Закладные: контур не задан - … нарисуйте блок закладной в библиотеке или запишите контур
в _контуры.json» (`sections.py`, в `beam_spans` добавлен артикул ригеля). Если закладная
не подобрана (ПОДОБРАТЬ) — контур не ищется, замечание одно (про крепление).
(13) Закладные ригелей вставляются **блоками из библиотеки** (`кп1336`, `кпс 830`, `кпс 1127`,
`кпс 2017`, `кпс 039`, `кпс 1278`, `кп45102`): точка вставки (0,0) - в плоскости стойки по оси
ригеля, X вдоль ригеля, правый конец - зеркалом; блоки грузятся в чертёж тем же механизмом,
что узлы (старые версии уходят в «имя (старый N)»). Приоритет: блок → контур `_контуры.json`
→ условный прямоугольник + замечание. `R.Library` кэшируется по mtime (DXF читается один раз
на процесс). Пользователь выравнивает базовые точки блоков `кпс 1127`/`кпс 2017` (x=−2) и
`кпс 039` (x=−6) под общее соглашение; `кп45102` - 3DSOLID (габарит программно не считается).
